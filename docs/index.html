How it works

A state machine you can trust.

Every corpus walks the same six states. Every transition is persisted to SQLite before the worker moves on — restart-proof, refresh-proof, audit-friendly.

QUEUED→ DOWNLOADING→ TOKENIZING→ EMBEDDING→ INDEXING→ READY

Failures route to a dead-letter queue — the consumer never silently retries. GET /api/training/{id} returns the full event timeline.

01 · UPLOAD

202, instantly

POST /upload streams the corpus to MinIO, inserts a QUEUED row in SQLite, publishes a message to RabbitMQ and returns a trainingId — the HTTP thread never blocks on training.

02 · QUEUE

Durable by default

A durable exchange feeds a consumer pool (2 workers by default) that drains the queue at its own pace. Malformed corpora are rejected into the DLQ for manual inspection.

03 · TRAIN

Tessera + Mosaic

The worker downloads the blob, trains byte-level BPE with Tessera, builds the Mosaic lookup table and indexes every sentence — persisting each state change as it goes.

04 · SERVE

Search from cache

Artifacts land in trained-models/{trainingId}/ on MinIO. Search, tokenize and compare resolve through an LRU cache that streams artifacts on demand.

Features

Production-shaped, demo-sized.

The architecture lessons are real — durable queues, idempotent consumers, state machines, graceful shutdown — at a scale you can read in an afternoon.

🧩

Byte-level BPE

Tessera tokenizes any UTF-8 corpus with no pre-built vocabulary — the same algorithm family GPT-style models use.

🎨

Lookup embeddings

Mosaic assigns each token a vector from a lookup table; sentences are mean-pooled and compared by cosine similarity.

📨

Queue-based training

Uploads return 202 immediately. RabbitMQ buffers the work; a consumer pool processes it without blocking HTTP.

🪣

Object storage

Corpora and model artifacts live in MinIO with TTL rules — real S3-style code paths without standing up AWS.

🗄️

SQLite state machine

Every transition persisted through Exposed in WAL mode. The dashboard reads the same rows the workers write.

☠️

Dead-letter queue

Failures park in the DLQ with the original payload intact — no silent retries, no swallowed errors.

📈

Prometheus metrics

/metrics exposes counters in Prometheus text format — uploads, trainings, searches, failures.

🐳

One command

App + MinIO + RabbitMQ + SQLite, all from a single docker compose up. JVM 21, Ktor 3, Kotlin 2.3.

About these results — honest by design

Mosaic provides embeddings as a lookup table — the vectors are randomly initialized, not trained. The pipeline (tokenization → vector lookup → mean pooling → cosine similarity) is real and identical to production-grade pipelines, but without training the similarities reflect random structure, not semantic meaning. Training (Word2Vec / GloVe / etc) is a separate future project.

Plain JSON over HTTP. The dashboard uses exactly this surface — nothing privileged.
